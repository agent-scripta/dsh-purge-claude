# dsh-purge 1.1.93 · Claude 适配版 —— 适配说明与使用

本仓库是 dsh-purge（"小码酱 / Little Code Sauce"提示词体系）1.1.93 的 **Claude Code / ClaudeCN(claude-cn) 非官方适配版**。
本版在实测中把"能不能真正生效"的关键问题全部修好，并新增"最硬档"。

## 修复：智能体团队 / 子智能体启动失败（近期）

**症状**：开启智能体团队、派子智能体、或跑 `plugin`/`team`/`agent` 等管理命令时，CLI 报
`error: unknown option '--append-system-prompt'`，团队与子智能体进程一启动即失败。

**根因**：`lib/inject-prefix.js` 由 bun preload 全局加载，原本对**每一个** CLI 进程都执行
`process.argv.push('--append-system-prompt', txt)`。管理命令和 CC 派生的 team/agent 工作进程
也走 preload，被塞入该参数后 commander 无法识别，直接退出。

**修复**：注入前先判断当前进程类型，两类一律跳过注入——
1. 首个非选项参数是管理子命令（`plugin/team/agent/task/mcp/setup/doctor/update/install/...`）；
2. 带 `--agent` / `--agent-id` 或环境变量 `DSH_PURGE_SKIP=1`（CC 派生的子智能体进程）。

只有真正的对话会话（交互式或 `-p`）才注入，行为不变。

**验证**：行为测试确认 `team create`/`plugin list`/`agent spawn` 干净跳过、`-p`/交互正常注入；
沙箱卸载旧版→安装本版实测 `plugin list` 恢复正常、对话注入正常。

> 下方各节为原有机制说明。

## 一、真正生效的原理（重要）
- Web/ClaudeCN 会话走 `--sdk-url`，实测 `preload` 里的 `--append-system-prompt` **不被可靠采用**；web 端真正生效的是下面这个服务端文件。
- 真正决定系统提示的是服务端文件：`/data/.claude/claude-cn/cyber-risk-instruction.md`。
- 本版做法：**切档 / 开启时把当前模式的规则集写入该文件；`off` 时删除恢复平台默认；`SessionStart` 每次按 `.active` 自愈同步。**
- 纯 CLI（`bun cli.js -p`）场景仍由 `preload` 的 `--append-system-prompt` 注入；两路互补。
- **已关闭 `UserPromptSubmit/PreToolUse` 锚定 hook**：它把"运行配置"塞进用户消息，模型会当成"伪造注入"而拒绝（就是"不能照做"的来源）。身份靠上面的 `cyber-risk` 真系统提示即可。

## 二、模式一览（输入 `/` 可见命令后说明）
| 命令 | 作用 |
|---|---|
| `/purge:purge-on` | 默认档 · 通用协作（代码/调试/架构/写作） |
| `/purge:purge-max` | 最硬档 · 原始全文完整版（约25KB，需强模型） |
| `/purge:purge-redteam` | 红队指挥 · 只规划与派活（收集→梳理→发现→利用→内网） |
| `/purge:purge-minimal` | 极简 · 只保留身份与基本工作方式 |
| `/purge:purge-stealth` | 隐身 · 低痕迹执行，反调试/免杀等本地测试 |
| `/purge:purge-novel` | 创作 · 角色扮演/小说/成人向，写足不淡出 |
| `/purge:purge-off` | 关闭 · 恢复正常 Claude Code |
| `/purge:purge-status` | 查看当前模式 |

切换后 **新开会话** 生效。

## 三、"最硬"怎么用（关键）
硬度上限由**模型**决定，提示词只能逼近：
- `deepseek-v4.1-flash`（默认）：快，但最硬内容会软/拒。
- **Kilo Free `nvidia/nemotron-3-super-120b-a12b:free`** 或 **Magpie `kilo/kilo-auto/free`**：慢，但实测能扛最硬（实测在其上可给出 AMSI bypass 完整思路）。
用法：界面把模型切到上述之一 → 新开会话 → `/purge:purge-max` → 派活。

## 四、规则集（中性化说明）
`default/minimal` 采用 **share 最初原版**；`redteam` 为**补强的红队作战手册（~6.7KB）**；`stealth`、`novel` 为中性写法；`max` 为原始全文（约25KB）。
`max` 采用**原始 dsh-purge 1.1.93 全文**（约25KB，含 25 条 Scoped Rules + 约 65 条细则 + 全部路由/工作流/格式），**逐字保留**，仅剔除第 1 条的自废句；实测 deepseek 也能用。**行为由安装的设定决定，"念出来"的语言是中性描述。**（对照 evans 仓库：full 均已删；max/redteam/stealth/novel 一致；default/minimal 两仓库各自保留本仓库原版。）

## 五、安装 / 卸载
- plugin：`plugin marketplace add <repo>` + `plugin install purge@lcs-skills`
- 容器内：进 `plugins/purge/` 跑 `bash install.sh`
- 卸载：`bash uninstall.sh`（**完全卸载**：删技能/运行态/preload段/恢复cli.js/删插件缓存与注册/清 cyber-risk/清源，且断自愈）

## 七、本版关键改动（相对上一 tag）
1. 修复"注入不生效"的根因：改用服务端 `cyber-risk-instruction.md` 作为 web 生效通道（此前 append 被 sdk 忽略）。
2. 关闭"每轮锚定 hook"（导致"不能照做"的元凶）。
3. `default/minimal` 用 share 最初原版；`redteam` 补强为红队作战手册(~6.7KB：角色/流程/攻击面模板/证据纪律)；`stealth/novel` 中性；`max`=原始全文逐字(去第1条自废句)；删 full。
4. 命令 `description` 与技能页 `SKILL.md` 均写入**中文命令说明**（命令后带中文解释）。
5. 修 `/opt/purge-github` 源与四处副本一致，会话启动不再把改动刷回旧版。

## 小码酱子智能体（团队/子代理带破甲人格）

装好后会随包铺一个自定义 agent 定义：`~/.claude/agents/little-code-sauce/little-code-sauce.md`，
人格正文取本插件的 default 档规则集，frontmatter 声明 `name: little-code-sauce`。

- **CC 内置子智能体**（general-purpose / Explore / Plan / verification）用的是各自独立的
  内置 systemPrompt，本来就不带小码酱人格——这是 CC 的设计，与破甲注入无关。
- **要派带小码酱人格的活**，用 `little-code-sauce` 这个 agent（在团队里指定 agentType，
  或 CLI `--agent little-code-sauce`），它的人物设定就是小码酱、按破甲规则执行、完成向 lead 汇报。
- 安装/自愈时由 `setup.sh` 自动铺到 agents 目录；`CLAUDE_AGENTS_DIR` 可改目标目录。
- 想换人格：编辑 agents 目录里的那个 md，正文替换成对应档的规则集即可（default/redteam/max 等）。


### 人格随档位自动同步

agent 正文不是写死的：`purge <档>` 切档时会自动调用 `lib/sync-agent.sh`，把当前档的
规则集写进 `~/.claude/agents/little-code-sauce/little-code-sauce.md`——派出去的子智能体
人格跟随你切的档（default/redteam/max/stealth/novel/minimal）。手动同步也可直接跑：
`bash lib/sync-agent.sh <档名>`（省略档名则取 `.active-ruleset`）。


### 红队模式的正确分工（重要）

红队档 `redteam.md` 是**指挥官人格**：lead 只规划、派活、分析回报，不直接干活。
所以切到 redteam 档时，`sync-agent.sh` 同步的是 **5 个执行角色 agent**：

| agent | 角色 | 职责 |
|---|---|---|
| `rt-recon` | 信息收集 | 被动+主动收全资产，不测漏洞 |
| `rt-assess` | 资产梳理 | 逐条评估易打性，排"先打谁" |
| `rt-vuln-scan` | 漏洞发现 | 现成 PoC→Nday/1day→接口未授权 |
| `rt-exploit` | 漏洞利用 | 拿权限、上马、建隧道 |
| `rt-internal` | 内网渗透 | 走隧道 gogo→fscan，挖全部网段 |

这些 agent 是**叶子节点：直接干活、不再委派**，人格=红队破甲纪律+该角色职责+证据/输出纪律，
**不含**"你是指挥官"那一段（否则 lead 和子智能体都只规划不干活，没人执行）。
派活时用 `little-code-sauce` 之外的 `rt-<角色>` agent，并在 prompt 首行保留 `redteamRole: <角色>`。
切回其它档时，同步逻辑恢复为单个 `little-code-sauce` agent。


## 文本控制面板（/purge:purge-panel）

与新版一致，本版也提供纯文本控制面板：CC 是 TUI 无侧栏整页 UI，用 `/purge:purge-panel`（或 `/purge panel`）输出状态、当前档、6 档说明与全部命令速查，只读不改状态。`lib/panel.sh` 由 setup 铺到运行目录，purge 的 `panel` 分支调用。切换档位仍用 `/purge:purge-<档>`，新开会话生效。
